# Путеводитель для поездки

Telegram Mini App и сайт: маршрут, билеты, жильё и заметки компании. Каждая поездка живёт по своей секретной ссылке.

## Файлы
- `index.html`: всё приложение.
- `config.js`: имя бота и адрес базы Firebase.
- `database.rules.json`: правила Realtime Database (публикуются вручную в консоли Firebase → Realtime Database → Rules).

## Как устроен доступ
- Поездка лежит в `trips/<id>`, где id — 22 случайных символа. Правила пускают только в пути длиной 16–64 символа и запрещают читать список поездок, поэтому чужую поездку не найти перебором.
- Ссылка-приглашение: `https://t.me/<бот>?startapp=<id>` (в Telegram) или `<сайт>/?t=<id>` (в браузере). Кто знает ссылку, тот может смотреть и редактировать.
- Без ссылки открывается экран «Мои поездки». Список хранится в localStorage и в Telegram CloudStorage.

## Хостинг
GitHub Pages: загрузить `index.html` и `config.js` в репозиторий. База: Firebase проект trip-guide-ffb87, тариф Spark (бесплатный), регион europe-west1.

## Ограничения бесплатного тарифа
Realtime Database: 1 ГБ данных, 10 ГБ скачивания в месяц, 100 одновременных подключений. Скрины и PDF хранятся в базе (до 6 МБ на файл), за ними стоит следить в Firebase → Realtime Database → Usage.

## Офлайн
- `sw.js` (service worker) хранит на устройстве страницу, библиотеки (Telegram, Leaflet, Firebase) и до 800 тайлов карты. Страница грузится из сети, а без сети или если ответа нет 3 секунды, открывается сохранённая копия.
- Данные поездки лежат в localStorage, скрины и PDF билетов в Cache API (`files-<id>`), они скачиваются заранее, пока есть сеть.
- Правки без сети пишутся в очередь `trip-pending-<id>` и досылаются при следующем подключении, даже если приложение закрывали. Прикрепить файл без сети нельзя.
- В Telegram на iPhone service worker не работает: без сети открыть приложение с нуля не получится, но уже открытое продолжит работать. На iPhone можно добавить сайт на экран «Домой» из Safari (`manifest.webmanifest`, иконки `icon-*.png`).
- При изменении `sw.js` поднимайте версию `V`, чтобы старый кэш страницы удалился.

## Редактор маршрута и отметки
- Города, даты и порядок меняются только в «✎ Изменить маршрут». Это черновик: правки подсвечиваются, соседние города держатся встык, в базу всё уходит по кнопке «Сохранить». Есть «↩ Шаг назад».
- Поездка на один день: остановка, у которой приезд и отъезд в один день. В сводке у неё вместо жилья стоит «1 день», а у возвращения «там же».
- При сохранении маршрута пустые заготовки «ищем жильё» и некупленные билеты без номера переезжают на новые даты. Забронированное жильё двигается, только если стояло встык с датами города. Купленные билеты не меняются.
- Отметки билетов и жилья в сводке тоже копятся как черновик: появляется панель «Не сохранено: N» с кнопками «Отменить» и «Сохранить».

## История изменений
- Каждое действие (сохранение маршрута, отметки в сводке, правка или удаление записи) пишется одной записью в `trips/<id>/log/<ключ по времени>`: кто, когда, что поменялось, и прежнее состояние каждой вещи.
- Экран «🕘 История» (под сводкой и в профиле): фильтры, «открыть ›» ведёт к записи, «↩ Вернуть как было» восстанавливает прежнее состояние и сам пишется в историю.
- Значок на кнопке показывает, сколько чужих изменений появилось с последнего просмотра истории на этом устройстве.
- Удаление записи больше не стирает её скрины, чтобы её можно было вернуть.

## Расходы
- Вкладка «💰 Расходы»: общие траты поездки и расчёт «кто кому переводит». Записи лежат в `trips/<id>/expenses/<id>`, настройки в `meta.money` (`base` основная валюта, `rates` свои курсы, `w` доли по умолчанию).
- Три вида записей: трата, перевод между участниками, доход на всех (например, вернули залог). Делить можно поровну, по долям, по суммам и по процентам.
- Любая валюта: у каждой записи свой курс к основной валюте (`rate`). Курс подставляется сам из бесплатной таблицы (currency-api, обновляется раз в полдня и хранится на устройстве), его можно поправить суммой в основной валюте или задать свой курс в настройках.
- Валюта и участники новой траты подставляются по маршруту: страна и состав компании на выбранную дату.
- «Кто кому»: минимальный набор переводов. Кнопка под долгом открывает готовый перевод, после сохранения долг гаснет. Нажатие на имя показывает, из чего сложился баланс.
- «Итоги»: доля каждого, категории, «Скопировать итог в чат», таблица CSV для Excel.
- Без сети всё работает как остальное приложение: записи копятся на устройстве и уходят в базу при появлении связи. Фото чека загружается только с интернетом.
- Все правки попадают в «🕘 Историю», оттуда же их можно вернуть.

## Просмотр и сохранение файлов

Ваучеры, билеты и чеки открываются в своём просмотрщике поверх приложения (`openFile`, блок «просмотр файлов»).

- PDF рисуется через pdf.js (`pdfjs-dist@3.11.174`, legacy-сборка с unpkg, подгружается при первом открытии и заранее, если в поездке есть PDF). Встроенный просмотр PDF в мини-приложении Telegram на Android не работает, на iPhone показывает только первую страницу.
- Масштаб: щипок, двойное нажатие, кнопки ＋ −, на ПК Ctrl + колесо. Закрыть: ✕, кнопка «назад» Telegram, Esc.
- Сохранить. Внутри Telegram обычное скачивание не работает (на Android в мини-приложениях оно выключено, на iPhone запрещено меню по долгому нажатию), поэтому:
  - iPhone: кнопка «Сохранить или отправить» открывает системное «Поделиться» с самим файлом;
  - Android и ПК в Telegram: «Скачать» открывает сайт в браузере по ссылке `?t=<поездка>&f=<файл>&dl=1`, там файл скачивается сам. На Android ссылка уходит с `try_browser: 'chrome'`, иначе она откроется во встроенном браузере Telegram, где скачивания тоже нет;
  - обычный браузер: «Скачать» и, на телефоне, «Поделиться».
- Ссылка `?t=…&f=…` открывает файл сразу, не дожидаясь подключения базы: файл читается обычным запросом к базе.
- Библиотека pdf.js заранее запрашивается в режиме `no-cors`, так же, как её потом грузит страница, иначе сохранённая копия не подойдёт.
